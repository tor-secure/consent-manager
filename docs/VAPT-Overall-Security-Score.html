Score explanation

1. Why this score

8.3 reflects a codebase that already has Clerk session auth, edge auth.protect(), org-scoped queries, operator RBAC on keys/webhooks/publish, CSRF fail-closed, SDK origin allowlisting, HMAC production secrets, and patched Next.js 16.3.4. It is not 9.0 because public APIs still use an in-process rate-limit map, tenant isolation is application-only (no RLS), and MFA / remaining npm highs are not verified in this repository.

2. Strongest controls

Clerk + webhook role mapping (invitees are no longer auto-Owner). Only Owner can assign Owner. Webhook delivery reuses the scanner SSRF guard with redirect: manual. Portable consent requires a Clerk session, not a spoofable Origin. Banner/SDK URLs and colors are sanitized. CSRF rejects cookie mutations with no Origin/Referer. Production boot fails without dedicated HMAC/webhook secrets.

3. Biggest weaknesses

Process-local rate limiting will not hold across serverless isolates. No Postgres row-level security. CI npm audit only fails on critical. Many routes still use console.error instead of the redacting logger. Clerk MFA is a dashboard setting, not evidenced here. Members can still CRUD websites, drafts, and vendors (operator-gated paths are the privileged ones).

4. Findings with the greatest score impact

SEC-011 (in-memory rate limit) is the main drag on API Security (7.9, 15% weight). SEC-024 (no RLS) and remaining Member write scope drag Authorization (20% weight). SEC-026-class transitive highs and critical-only CI drag Dependencies. SEC-022 console.error drags Data Protection. No confirmed Critical remains, so the 4.0 cap rule does not apply.

5. To reach 8/10

Already met. Keep production secrets and the Clerk membership webhook configured; do not regress Owner-grant, SSRF, CSRF, or origin allowlist controls.

6. To reach 9/10

Ship distributed rate limiting (Redis/Upstash/KV) and stop trusting spoofable X-Forwarded-For. Add Postgres RLS (or equivalent) for organization_id. Verify Clerk MFA on the production tenant. Raise CI to npm audit --audit-level=high and clear remaining highs. Replace console.error with the structured logger.

7. To reach 10/10

Also: transactional last-Owner protection, sanitize vendor URLs on write (not only SDK render), split public health vs authenticated readiness, least-privilege Member (read/draft only), secret scanning in CI, SIEM/alerting on Owner changes and key/webhook create, and a two-tenant live retest that verifies the remediations — not just that recommendations exist.
