# Enterprise UI redesign

The DPDP experience now has a Three.js overview hero and seven scene models in scroll-stacking chapter tiles on hydrated desktop layouts with motion enabled. Scrolling scales and tilts covered tiles behind the next chapter; compact, short-viewport and reduced-motion layouts retain ordinary reading flow. Minimal captions sit beside each model; native information windows hold fuller explanations. Scroll moves the chapter-specific mechanisms and changes depth/light; pointer movement gently tilts the camera. The orb appears only in the Overview hero. There is no idle animation loop.

The overview connects notice pages, choice paths, a guardian checkpoint and evidence plates. Each later scene has a unique model: compass, book, switch console, keyed plugs, guardian portal, vault and evidence archive. In desktop stacking mode, only the active and next chapter may mount a live stage within an 80px viewport margin. In normal reading flow, each stage uses the viewport gate alone, so mobile and short viewports render the real Three.js figures when visible, enabled and motion is allowed. Distant stages release their resources. Rendering density is capped at 1.25 below 768px and 1.5 on desktop, recalculated by ResizeObserver; canvas touch-action is pan-y. State changes settle briefly, including bounded purpose-branch packet flow, then rendering stops. Mobile and short viewports retain real Three.js models in ordinary reading flow. Diagrams and equivalent DOM controls remain available for reduced motion, server rendering/no JavaScript and WebGL failure.

## Scope

The application shell, shared dashboard controls, navigation, feature indexes, and public marketing presentation use a navy/teal enterprise design. Existing routes, API authorization, consent semantics, database models, and migrations are unchanged.

The expanded redesign inventories **109 page modules** in [ui-route-coverage.md](ui-route-coverage.md). It uses shared page families and specialized readers; it does not claim that each route received a bespoke layout or individual authenticated browser review.

The second pass adds:

- DPDP Act: a complete-flow overview hero and seven fixed models in alternating green/ivory scene panels, with short captions and compact native detail windows. Memory-only purpose choices, withdrawal, history, a guardian illustration and an evidence example use ordinary controls. The summary shows optional paths; one native full-guide disclosure retains all thirteen original chapters and deep links.
- Solutions and regulation pages: editorial split layouts, controlled capability/process decks, and searchable FAQs.
- Pricing: keyboard-accessible plan exploration and a complete comparison alongside the existing enquiry form.
- Privacy documents: searchable section navigation, native disclosures, expand/collapse all, and print presentation.
- Blogs/news: searchable editorial article library, topic filtering, full article outline, and news search. Article prose stays fully readable.
- Learning: paced paragraph reading with an optional complete module transcript.
- Dashboard: related-tool navigation, guidance beside form fields, clearer metric/empty states, transfer/activity/security tabs, and creation disclosures for transfers and experiments.
- Motion: route entrances, visible-by-default section entrances, carousel transitions, disclosure transitions, and interaction feedback. Reduced motion remains supported. The mobile contact action occupies normal document flow so it cannot obscure controls.

Specialized experiences added:

- Runtime discovery: accessible observation drawer with page, destination, consent context, and provenance.
- Privacy Graph: searchable map/list, entity and provenance filters, relationship inspector, evidence references, and existing read-only purpose simulation.
- Digital Twin: default dependency map and optional lazy-loaded Three.js view of actual configured relationships. Keyboard controls, entity selector, bounded rendering, and WebGL fallback retain a structured alternative.
- Consent evidence: session, policy, decision, and proof timeline using existing evidence.
- Browser crawler: bounded progress polling, background-tab pause, cancellation on unmount, and completion refresh.
- Public website: redesigned hero and interactive illustrative consent/discovery/evidence workflow, shared navigation, pricing and solution presentation.

Motion is provided by one library, `motion`, with reduced-motion support. Digital Twin Three.js loads after selecting 3D exploration; DPDP lazy-loads each illustrative stage near the viewport. Both render on scroll or interaction rather than continuously. Fonts are locally packaged and self-hosted. No GSAP or Anime.js dependency is required.

The latest public typography uses locally packaged Manrope; dashboard headings share it while operational body text retains Geist. Instrument Serif italic supplies the DPDP editorial emphasis. Font files are loaded through `next/font/local`; there are no browser requests to a font provider. Shared public panels now have broader curved edges.

## Interactive privacy exhibit behavior

The DPDP overview hero uses two equal columns, 2rem gap, 64px top/52px bottom padding and a 720px minimum height. Its 470px-high model anchors notice, choice, safeguards and evidence in one overview. Below 1000px the hero stacks and its stage becomes 390px tall. The seven mounted scene articles form a scroll-stacking tile gallery on hydrated desktop layouts with motion enabled. Zero-height natural-flow markers track the original chapter positions. Sticky tiles start at 164px plus 10px per chapter, with increasing z-index, 140px trailing spacing, a 1400px gallery perspective and top-centered transforms. Previous tiles shrink from 1 to 0.92 and tilt from 0 to -2 degrees as scrolling advances; their covered controls become inert. For viewport heights from 701px to 850px, chapter offsets narrow to 6px, panel padding becomes 20px and model stages become 280px tall. Compact layouts, heights at most 700px, reduced motion and SSR retain ordinary reading flow. A ResizeObserver also measures each tile against its sticky top and a 16px viewport reserve. If any tile cannot fit, including an expanded withdrawal history, the journey switches to ordinary reading flow even above the compact breakpoints. A layout effect preserves the active chapter at a 140px reading offset; viewport resizing retries the stack. Desktop scene panels use 1.05fr/1fr columns, a 32px to 90px gap, 490px minimum height and 36px corners. At widths of 1100px and above, even panels reverse the visual and copy; each visual stays within its own panel. Stage heights are 410px desktop and 350px below 1000px. Progression sticks at 80px desktop and 64px compact and scrolls horizontally when necessary. Widths below 768px and viewport heights at most 700px use stacked, auto-height panels and 280px model stages with real Three.js renders. These layout thresholds no longer disable WebGL. Reduced motion, SSR/pre-hydration, no JavaScript and WebGL failure show diagrams with the same DOM controls. Native detail windows are at most 560px wide, viewport width minus 32px, and 85dvh tall. The complete reference remains one native disclosure containing thirteen continuous chapter articles, with chapter hash links and a full-guide open/close control. The contact speech bubble is hidden on this page. Other legal readers, plan details and shared forms become one column at 760px; legal reading uses a 230px index and 64px gap, articles a 210px index and 48px gap, stacking at 800px. The article library combines a featured story with two columns of bordered rows, becoming one column at 800px. Pricing pairs a 280px plan index with a two-column detail area and a complete comparison disclosure. Tile motion uses natural-flow markers and a stiffness-180/damping-36 spring; every model remains inside its own panel. Progression navigation targets those original markers. Covered tile controls are inert. `src/app/privacy-experience.css` governs the current composition and supersedes the earlier travelling-stage styles.
