Biggest strengths

  • Real multi-tenant model (organizationId / website ownership) with Clerk + local org/membership bootstrap.
  • Live JS SDK (/api/sdk/script, /api/sdk/[siteKey]/config) with banner + preference center and /api/consent/record.
  • Consent records / decisions / events, cryptographic evidence, DB-backed analytics.
  • Banner Studio persists into policy version configuration and feeds the SDK.
  • HTML scanner (not mocked), scheduled scans via cron, drift/risk/quality from real findings.
  • Developer primitives: hashed API keys at rest, webhooks with delivery attempts.

Biggest gaps

  • No product report exports (CSV/PDF/Excel) or scheduled report delivery.
  • RBAC permissions table is display-only; most APIs allow any org member.
  • Integrations catalog = local DB association, not OAuth/vendor APIs (GCM/IAB signals are more real).
  • API keys are created but not used to authenticate API calls.
  • DSAR: intake + status + erasure automation; no access data package / portability / CCPA-style opt-out suite.
  • Overview lacks consent rate card, date-range UI, exports, and quick-action hub.
  • Script enforcement depends on data-cmp-purpose tagging; cookies/untagged third parties not fully blocked.

  • Auth + org workspace (Clerk, bootstrap, dashboard gate).
  • Websites: create/list/detail/settings, environments field, domain verification, jurisdiction rules, scan schedule, installation snippet.
  • Purposes & vendors: create/list, policy associations.
  • Policies: version, publish, Banner Studio, preference preview writing real consent.

6. UI-Only / Stub Features

  • Integrations catalog Connect — empty configuration; no OAuth.
  • Sidebar Billing — navigates to Organization Settings; billing schemas unused.
  • Sidebar SDK / Installation — points to API Keys, not website installation.
  • Permissions matrix — display only; not checked in handlers.
  • Firewall scenarios — preview simulator on real graph (not a fake table, but not a live appliance).
  • Overview date locked to 30 days (real data, non-functional filter).

Core consent/analytics/scanner pages were not found to use mock visitor tables.

7. Missing Features (Prioritized)

P0 — Critical

  • Enforce fine-grained RBAC (or document all members as operators).
  • Fix membership bootstrap so non-owners are not minted as Owner.
  • API key authentication for machine APIs or remove misleading API Keys claim.
  • Consent/log export (CSV/JSON) for audits.
  • Website delete (or soft-delete) with cascading safety.

P1 — High

  • Report center (CSV first; PDF later); DSAR access package; purpose/vendor edit-delete; email alerts; domain-verify gating; stronger enforcement + docs.

P2 — Medium

  • Overview quick actions + date-range + consent rate; cookie classify/history; preference history / re-consent UX; real integrations or shrink catalog; pagination.

P3 — Nice to have

  • React/Next packages; mobile SDKs; scheduled email reports; Excel; headless scanner; SSO/SCIM UI; billing productization.

11. Implementation Roadmap

  1. Phase 1 — Critical foundation: RBAC baseline; Owner bootstrap fix; website delete; API key auth or UI honesty; consent CSV export; audit coverage; secret hardening.
  2. Phase 2 — Core Consent Management: Purpose/vendor edit-delete; cookie classify workflow; enforcement hardening; domain-verify policy; overview date filter + quick actions + consent rate.
  3. Phase 3 — Analytics & Reporting: Report builder (CSV→PDF); consent/cookie/scan/DSAR reports; scheduled exports; pagination.
  4. Phase 4 — Privacy / DSAR: Identity verification; access package; correction apply; portability; CCPA opt-out/restrict; SLA email nudges.
  5. Phase 5 — Compliance: Regulation packs tied to real controls; geo banner tests; compliance report from control evidence.
  6. Phase 6 — Developer / API: Documented public API with key scopes; Next helper package; webhook catalog polish; sandbox keys.
  7. Phase 7 — Enterprise: SSO/SCIM; website-level roles; billing/usage limits; email alert center; headless scanner; vendor OAuth.
